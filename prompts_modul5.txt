--- Diapositiva 26 · Comparar frases amb la similitud del cosinus ---

[PROMPT PAS 1]
Crea un paquet de Python anomenat helpdesk_lab que pugui executar com a eina de línia d'ordres amb `uv run python -m helpdesk_lab <ordre>`. Fes servir subordres d'argparse: cada exercici del curs hi afegirà una ordre nova.
La primera ordre és `cosine`. Agafa tres frases d'exemple: "reset account password", "change password" i "submit travel receipt". Converteix cada frase en un vector de recompte de paraules sobre un vocabulari compartit, i mostra el vocabulari i els tres vectors.

[PROMPT PAS 2]
Ara fes que `cosine` rebi una frase de consulta. Converteix-la en vector de la mateixa manera i calcula la similitud del cosinus amb cada frase, a mà amb Python pur i sense biblioteques, perquè pugui seguir els càlculs. Mostra les frases de més a menys semblant amb tres decimals. Si la consulta no comparteix cap paraula, mostra "No shared words".

--- Diapositiva 29 · Calcular els embeddings i desar-los a Chroma ---

[PROMPT]
Vull desar els fragments en una base de dades Chroma al disc, a var/chroma, perquè es conservin entre execucions.
– Posa els noms dels models a config.py: xat gemma4:e2b i embeddings bge-m3, servits pel meu Ollama local. Que es puguin canviar amb variables d'entorn.
– Crea llm.py, un petit client de l'API HTTP d'Ollama (/api/embed i /api/chat) per obtenir embeddings i respostes de xat, només amb la biblioteca estàndard. El portàtil té poca RAM, així que: demana a Ollama que descarregui cada model en acabar (keep_alive), desactiva el mode thinking de Gemma 4 (think: false) i limita el context del xat a NUM_CTX tokens (a config.py, 4096 per defecte, canviable amb una variable d'entorn).
– Crea index.py amb un PersistentClient de chromadb: calculem els embeddings nosaltres amb llm.py (que Chroma no faci servir el seu model), amb similitud del cosinus, i la col·lecció porta el nom del model d'embeddings perquè no es barregin mai vectors de models diferents.
– Afegeix una ordre `index` que indexi tots els fragments i mostri el nom de la col·lecció, el nombre de files i la mida del vector.

[PROMPT]
Crea classifier.py i una ordre `classify MISSATGE`. Gemma llegeix el missatge d'un empleat i decideix si és d'IT, HR o Expenses, o de cap si és vague o barreja temes.
– Descriu cada categoria a les instruccions amb exemples dels nostres documents: IT són contrasenyes, VPN, portàtils…; HR són vacances, teletreball, ascensos…; Expenses són despeses, rebuts, hotels…

--- Diapositiva 45 · Enrutar peticions amb LangGraph ---

[PROMPT]
Construeix un assistent de suport amb LangGraph a workflow.py (un StateGraph amb un estat tipat i arestes condicionals), amb una ordre `workflow MISSATGE` que mostri la categoria, la ruta i el resultat.
– Primer pas: classificar el missatge amb el nostre classificador.
– Després, decidir on anar: ticket si la persona demana obrir un tiquet i descriu un problema real; clarify si demana un tiquet sense descriure el problema (per exemple "Please open an IT ticket.") o si el missatge és massa vague per classificar-lo; answer en tots els altres casos, amb el nostre RAG filtrat per la categoria del missatge. Les peticions de tiquet poden arribar en anglès, castellà o català ("ticket", "tiquet", "incidencia", "incidència").
– clarify només demana més detalls amablement.
– Per als tiquets, crea tickets.py, un sistema de tiquets simulat que desa cada tiquet com una línia JSON a var/tickets.jsonl, amb un ID com TCK-1A2B3C4D, la categoria, el resum i la data. De moment, el pas ticket el crida directament.

--- Diapositiva 55 · Crear un servidor MCP per a l'app de tiquets ---

[PROMPT]
Converteix el nostre sistema de tiquets en un servidor MCP a mcp_server.py, amb MCPServer de l'SDK oficial de MCP per a Python, versió 2 (from mcp.server import MCPServer), que s'executi en local per stdio. Anomena'l "helpdesk-tickets". Ha d'oferir:
– una eina per crear un tiquet a partir d'una categoria i un resum, que retorni l'ID del tiquet. Si la categoria no és IT, HR o Expenses, ha de retornar un error clar amb les opcions vàlides;
– una eina per llistar els últims tiquets, opcionalment només d'una categoria;
– una eina per cercar a les polítiques que reutilitzi la nostra cerca semàntica i retorni IDs, similitud i text;
– un recurs de només lectura "tickets://recent" amb els 10 últims tiquets.
Escriu una descripció clara per a cada eina, perquè la llegeix la IA. Assegura't que l'eina de crear tiquets declari què retorna (un TypedDict), perquè els clients rebin dades estructurades i no només text. Per a entrades incorrectes, llança un ToolError (from mcp.server.mcpserver.exceptions import ToolError). Recorda que un servidor stdio no pot escriure res a la sortida estàndard.
